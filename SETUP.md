# Подключение к Telegram и amoCRM (упрощённый вариант, без Node/Python-сервера)

Это пошаговая инструкция для "оптимально простого" варианта: статический
хостинг для Mini App, Google Apps Script вместо полноценного backend-сервера,
Google Sheets вместо базы данных. Кода из `backend-apps-script/` достаточно —
ничего устанавливать локально не нужно, всё живёт в браузере (script.google.com,
GitHub, Telegram, amoCRM).

Всего 5 частей. Делать по порядку — каждая следующая зависит от предыдущей.

---

## Часть 1. Разместить Mini App на хостинге (GitHub Pages)

Telegram требует HTTPS-адрес для Mini App — GitHub Pages даёт его бесплатно.

1. Создать репозиторий на GitHub (можно приватный), загрузить туда содержимое
   папки `wtusa-self-app/` (весь этот проект — `index.html`, `css/`, `js/`, кроме `backend-apps-script/`, он не нужен на хостинге).
2. В репозитории: Settings → Pages → Source: `main` branch, `/ (root)`.
3. Через минуту-две адрес вида `https://<ваш-логин>.github.io/<репозиторий>/`
   станет рабочим — откройте `index.html` в браузере, чтобы проверить, что
   всё грузится (пока ещё на mock-данных).

*(Альтернатива: Vercel/Netlify — тоже бесплатно, просто перетащить папку в
их веб-интерфейс. Технически без разницы.)*

## Часть 2. Google Sheet + Apps Script (backend)

### 2.1. Создать таблицу
Google Sheets → New spreadsheet. Скопируйте её ID из адресной строки
(`https://docs.google.com/spreadsheets/d/`**`ЭТА_ЧАСТЬ`**`/edit`).

### 2.2. Создать Apps Script проект
В этой же таблице: Extensions → Apps Script. Откроется редактор — удалите
файл `Code.gs` по умолчанию и создайте 9 файлов с именами и содержимым из
папки `backend-apps-script/` этого проекта:

```
Config.gs   Sheets.gs   Auth.gs   AmoCRM.gs   Telegram.gs
Webhooks.gs   Api.gs   Reminders.gs   Setup.gs
```

(В Apps Script расширение всегда `.gs` — просто создавайте файл с нужным
именем и вставляйте содержимое.)

### 2.3. Заполнить Script Properties
Project Settings (⚙️ слева) → Script Properties → Add script property.
На этом шаге заполните пока только:

| Ключ | Значение |
|---|---|
| `SHEET_ID` | ID таблицы из шага 2.1 |
| `TELEGRAM_BOT_TOKEN` | получите в Части 3 |
| `WEBHOOK_SECRET` | придумайте любую случайную строку, например `wtusa_9f3k2m` |

Остальные (`AMO_*`, `FIELD_ID_*`) заполним в Части 4.

### 2.4. Создать вкладки таблицы
В редакторе Apps Script выберите функцию `createSheetsIfMissing` в выпадающем
списке сверху → Run. Разрешите нужные права доступа (Google спросит один раз).
После выполнения в таблице появятся вкладки Participants, Documents, Payments,
Briefings, VisaInfo, PreDepartureChecklist, LinkTokens, SupportMessages, EventLog,
Events, EventInvitations, Coordinators.

*Если позже меняете список полей в `SHEET_SCHEMA` (Setup.gs) — например при
обновлении кода — запустите `createSheetsIfMissing` ещё раз, оно безопасно:
существующие вкладки не трогает, только добавляет недостающие столбцы/вкладки.*

Опционально: запустите `seedExampleBriefings`, чтобы не начинать с пустого
списка брифингов.

**Вкладка Coordinators** — обязательно заполните вручную (авто-создание
только добавляет заголовки, без строк): по одной строке на каждого
координатора — `amo_user_id` (числовой id пользователя в amoCRM, смотрите в
Настройки → Пользователи), `name`, `telegram_username` (без @, на это имя
жмёт студент в приложении, кнопка «Написать координатору»), `avatar_url`
(необязательно). Без этой вкладки синхронизация делок из amoCRM просто не
будет работать — координатор для каждой сделки ищется по `amo_user_id` на
каждом вебхуке.

### 2.5. Развернуть как Web App
Deploy → New deployment → тип **Web app**:
- Execute as: **Me**
- Who has access: **Anyone**

Скопируйте выданный URL (вида `https://script.google.com/macros/s/AKfycb.../exec`)
— он понадобится в Части 3 и 5.

*Каждый раз, когда меняете код .gs-файлов, нужно делать новый деплой (Deploy →
Manage deployments → ✎ → New version), иначе Telegram/amoCRM продолжат
дёргать старую версию кода.*

## Часть 3. Telegram-бот

1. Написать [@BotFather](https://t.me/BotFather) → `/newbot` → задать имя и
   username → получите **токен бота**. Вставьте его в Script Property
   `TELEGRAM_BOT_TOKEN` (Часть 2.3).
2. `/newapp` → выбрать вашего бота → указать HTTPS-адрес из Части 1
   (`.../index.html`) как Web App URL, загрузить иконку 640×360.
3. Опционально `/setmenubutton` → указать текст кнопки ("Моя программа") и
   тот же URL — тогда Mini App будет открываться прямо из меню чата с ботом.

Уведомления боту отдельно настраивать не нужно — он не принимает входящие
сообщения, а только отправляет (это делает Apps Script через
`sendTelegramMessage`, см. `Telegram.gs`) — так проще и не требует webhook
на стороне бота.

## Часть 4. amoCRM

### 4.1. Кастомные поля
В amoCRM: Настройки → Поля сделок → добавить (минимум, по ТЗ §44–52):
`Season`, `Program`, `CIEE ID`, `Payment #1 Status/Deadline/Paid Date` (и
аналогично #2, #3), `CIEE Registration Date` — остальные поля из ТЗ можно
добавить позже по мере необходимости, скрипт работает и без них (просто
не будет подтягивать эти данные).

### 4.2. Воронка SELF
Настройки → Воронки → создать воронку с этапами из ТЗ §53
(ОФОРМИЛСЯ → РЕГИСТРАЦИЯ CIEE → ... → READY TO FLY).

### 4.3. OAuth-интеграция
Настройки → Интеграции → Создать интеграцию:
- Redirect URI: URL из Части 2.5 + `?action=amoOauthCallback`
  (например `https://script.google.com/macros/s/AKfycb.../exec?action=amoOauthCallback`)
- Скопируйте Client ID и Client Secret → в Script Properties: `AMO_CLIENT_ID`,
  `AMO_CLIENT_SECRET`, `AMO_REDIRECT_URI` (тот же URL, что выше),
  `AMO_SUBDOMAIN` (то, что перед `.amocrm.ru` в адресе вашего amoCRM).

### 4.4. Одноразовая авторизация
В Apps Script запустите функцию `logAmoAuthorizeUrl`, откройте ссылку из
логов в браузере, залогиненном в нужный amoCRM-аккаунт, подтвердите доступ.
Вас перенаправит на `...?action=amoOauthCallback&code=...` — скрипт сам
обменяет код на токены и сохранит их в Script Properties (`AMO_ACCESS_TOKEN`,
`AMO_REFRESH_TOKEN`) — токен дальше обновляется автоматически.

### 4.5. ID кастомных полей и статусов
Запустите `listAmoCustomFields` — в логах появятся числовые ID полей,
разложите их по свойствам `FIELD_ID_SEASON`, `FIELD_ID_PROGRAM`,
`FIELD_ID_CIEE_ID`, `FIELD_ID_PAY1_STATUS`, `FIELD_ID_PAY1_DEADLINE`,
`FIELD_ID_PAY1_PAID_DATE` (и pay2/pay3 аналогично).

Запустите `listAmoPipelineStatuses` — в логах появятся `status_id` каждого
этапа воронки. Постройте JSON вида
```json
{"12345678":"SPONSOR_REVIEW", "23456789":"ABC_REVIEW", "34567890":"PLACED"}
```
(id этапов должны совпадать со списком `STAGE_IDS` в `Config.gs`, который в
свою очередь совпадает с `js/config/roadmap.config.js` на фронтенде) и
сохраните строкой в Script Property `STATUS_ID_MAP_JSON`.

### 4.6. Вебхук на изменение сделки
Настройки → Вебхуки → Добавить:
- URL: URL из Части 2.5 + `?action=amoWebhook&secret=<ваш WEBHOOK_SECRET>`
- События: "Изменение статуса сделки" (и опционально "Изменение сделки")

## Часть 5. Финальная сборка

1. В `js/services/config.js` фронтенда впишите `BACKEND_URL` = URL из Части 2.5,
   закоммитьте и обновите GitHub Pages (или другой хостинг) — с этого момента
   Mini App перестаёт использовать mock-данные и demo-панель (⚙️) пропадает
   сама, как только `BACKEND_URL` не пустой.
2. Настройте напоминания: в Apps Script → Triggers (часики слева) → Add
   trigger → функция `sendScheduledReminders` → Time-driven → Day timer.
3. **Привязка участника к сделке** (ТЗ §58): в Apps Script вручную выполните
   `createLinkToken("<amo_deal_id>")` (временно допишите строку вызова с
   нужным ID сделки в любую функцию и запустите, посмотрите токен в логах),
   отправьте участнику персональную ссылку:
   `https://t.me/<bot_username>/<app_name>?startapp=link_<токен>`.
   Участник откроет её в Telegram → Mini App сам вызовет линковку — сделка
   свяжется с его Telegram ID автоматически.

### Проверка
- Откройте Mini App у тестового аккаунта — должен создаться пустой
  Participants-ряд с дефолтными документами/чек-листом.
- Привяжите его к тестовой сделке через `link_<токен>`.
- В amoCRM переведите сделку на следующий этап — в течение секунд Mini App
  (при обновлении) и Telegram (уведомление) должны отразить новый статус.
- Проверьте, что вебхук реально стреляет: Apps Script → Executions — там
  будет видна каждая обработка `amoWebhook`.

## Ограничения этого варианта (осознанно, ради простоты)

- Google Apps Script имеет дневные квоты — по официальным лимитам Google
  (developers.google.com/apps-script/guides/services/quotas) на обычном
  аккаунте это 20 000 вызовов UrlFetch/день, 30 одновременных выполнений
  скрипта и 90 минут суммарного времени триггеров/день. Это лимит не на
  количество участников, а на то, сколько запросов физически прилетает в
  одну и ту же секунду — на несколько сотен студентов, открывающих
  приложение не синхронно (проверка статуса, запись на брифинг и т.п.),
  этого с большим запасом хватает; при случайном всплеске (например,
  координатор разослал уведомление) лишние запросы просто на несколько
  секунд встают в очередь, а не падают с ошибкой. Переезд на Node/Python
  backend имеет смысл не при росте числа участников, а если появится
  реально синхронная нагрузка на порядок выше — например, интеграция с
  системой, которая шлёт тысячи вебхуков в секунду. Контракт
  `js/services/api.js` (через `liveApi.js`) к такому переезду уже готов,
  менять фронтенд не придётся.
- Загрузка документов сейчас просто помечает статус "на проверке" — сам файл
  никуда не сохраняется (в `Api.gs` есть комментарий, куда добавить
  `DriveApp.createFile(...)`, если нужно реально принимать файлы).
- `changesRequiredVariant` (альтернативный текст "Требуются исправления" для
  CIEE/DS-160) в `roadmap.config.js` пока не подключён к реальному
  статусу — сейчас Roadmap отражает только `current_stage_id`. Если нужно
  различать "на проверке" и "требуются исправления" в рамках одного этапа —
  используйте отдельные статусы амоCRM/пункты `STATUS_ID_MAP_JSON`.
